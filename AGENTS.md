# Правила проекта sci-witch для агентов

Этот файл читает любой агент, который меняет код в этом репозитории: Claude,
Grok, кто угодно ещё. Правила собраны из решений владельца проекта. Их не
обсуждают в каждой задаче заново.

## Чего нельзя никогда

- Коммиты, push, PR, merge, теги, релизы. Изменения остаются в рабочем дереве
  до отдельного разрешения владельца.
- Работать в одном рабочем дереве одновременно с другим агентом. Параллельная
  сессия однажды сломала сборку посреди чужой работы.
- Менять опубликованные данные: `research/data/dev-seed-v1.jsonl`, `dev-seed-v2`,
  `ambiguous-v1`, `nomenclature-v1`, `prose-negatives-v1` и любой корпус, чей
  SHA-256 записан в манифесте. Новые данные — только новой версией корпуса с
  новым манифестом и SHA-256.
- Оставлять в проекте `target/`, модели, архивы, сборочные артефакты.
  Сборка — только с `CARGO_TARGET_DIR` во временном каталоге вне проекта;
  его размер сообщить, каталог удалить.
- Облачные API, телеметрия, Python runtime и ML в пути продукта. Продукт
  полностью локальный, на Rust.

## Что продукт обещает

Продукт — компилятор текста в научную структуру:
[`docs/compiler/COMPILER_CONTRACT_RU.md`](docs/compiler/COMPILER_CONTRACT_RU.md).
ASR (`sciwhisper-asr`) и сборщик голосового корпуса (`sciwhisper collect-voice`) —
исследовательские инструменты: они нужны вопросам 1–2 плана (выбор среди
N-best гипотез Whisper, калибровка на живых дикторах). Голосовое приложение
(трей, вставка, обновление, упаковка) снято 04.10.2026; последнее состояние —
тег `app-0.5-final`. Новых функций приложения в репозиторий не добавляют.

- Обычная речь не становится формулой. Название вещества и количество (число с
  единицей) внутри обычной фразы упомянуты, а не продиктованы, и не подменяются.
- `confidence` — уровень разбора, не вероятность. Не называть его вероятностью.
- Любой предел времени, глубины или числа кандидатов — явная константа и тест.
- Нельзя поднимать точность ценой роста опасных переписываний.
- Нельзя выдавать ограниченный разбор за полную поддержку чего-либо (IUPAC и т. п.).
- Стабильная поверхность ядра закреплена в
  `crates/sciwhisper-core/tests/public_surface.rs`. Сломал — это дефект выпуска.

## Прежде чем сказать «готово»

Эти четыре правила взяты из настоящих дыр, найденных в этом репозитории.

1. **Для каждой проверки безопасности напиши тест, который пытается пройти её
   неправильно.** Пример: ворота компилятора проходили на корпусе без обычной
   речи — видели 0 из 0 и считали это проходом. Пример: у выбора гипотезы n-best
   были тесты «чинит опечатку» и ни одного «не выдумывает формулу», и «водка»
   превращалась в H₂O.
2. **Меняешь значение по умолчанию, сигнатуру, зависимость — найди всех, кто на
   неё опирается** (`grep -rn`), и перечисли их в отчёте. Пример: смена умолчания
   у `gate` молча переключила ворота выпуска в `release.yml` (файл снят 04.10.2026, см. тег `app-0.5-final`). Пример: новая
   dev-зависимость без обновления `packaging/THIRD-PARTY-LICENSES.json` роняла
   тест лицензий.
3. **Прогони все проверки до конца и прочитай, сколько бинарей реально
   запустилось.** Упавший тест останавливает прогон на своём крейте, и
   остальные крейты молча не проверяются. Пример: тест лицензий останавливал
   прогон на 20 бинарях из 28, и никто этого не заметил.
4. **Сверь текст документа с кодом.** Каждое имя функции, файл и число, которые
   цитирует документ, должны существовать. Пример: в контракте было определение
   публичного API, которое не совпадало с тем, как работает `pub mod`.

Если исправление касается одного места вызова — найди остальные. Недоделанное
исправление (починен один вызов из двух) — самая частая дыра в этом проекте.

## Проверки

Все пять — во временном `CARGO_TARGET_DIR`:

```bash
cargo test --workspace --locked
cargo test -p sciwhisper-core --release --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
git diff --check
```

Если менялось ядро, разбор или корпуса — ещё ворота компилятора:

```bash
cargo run -p sciwhisper-eval -- gate \
  --report research/results/deterministic-v6.json \
  --report research/results/ambiguous-auto-v2.json \
  --report research/results/nomenclature-v1.json \
  --report research/results/prose-negatives-v2.json
```

Тесты считать по строкам `test result:` — отдельно число прошедших и число
**упавших бинарей**. Сводка через `awk` по позициям полей уже однажды показала
«0 failed» при настоящем провале.

## Оболочка — zsh

- `$VAR` не разбивается на слова: `$OPTS` с пробелами уйдёт одним аргументом.
- Шаблон в аргументе раскрывается оболочкой: `--include='*.rs'`, а не
  `--include=*.rs` — иначе `grep` не запустится вовсе.
- `set -e` не спасает от «command not found» внутри подстановок.
- Проверяй результат **по содержимому файлов**, а не по своему сообщению
  «всё прошло». Такое сообщение уже однажды печаталось, когда не запустилась
  ни одна команда.

## Отчёт

В конце работы — не пересказ, а сырой вывод:

- какие файлы изменены и зачем;
- какие команды выполнены и с каким кодом выхода;
- сколько бинарей тестов запущено, сколько упало, сколько тестов прошло;
- кого затронуло изменение (результат `grep`) и что с этим сделано;
- какие тесты «пройти неправильно» добавлены;
- что не сделано и почему. «Не сделал» лучше, чем «сделал», которое не проверено.

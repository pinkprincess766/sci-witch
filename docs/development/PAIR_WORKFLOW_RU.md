# Работа в паре: Claude — шеф, Grok — стажёр

Grok пишет быстро и дёшево. Claude ставит задачу, проверяет работу и либо
принимает её, либо возвращает с замечаниями. Текст между ними никто не
пересылает руками, и экран не нужен: Grok вызывается из командной строки
без интерфейса, скриптом [`scripts/pair/grok-task.sh`](../../scripts/pair/grok-task.sh).

Правила проекта для обоих — [`AGENTS.md`](../../AGENTS.md). Скрипт передаёт
их Grok при каждом запуске (`--rules`), а не надеется, что он найдёт файл
сам. Проверка показала, что `AGENTS.md` и `CLAUDE.md` в этом каталоге Grok
сам не подхватывает.

## Как пользоваться

Владелец пишет Claude: «поручи Гроку …». Дальше Claude:

```bash
scripts/pair/grok-task.sh start задача.md          # раунд 1: Grok работает в своей копии
scripts/pair/grok-task.sh check RUN [quick]        # проверки шефа в копии Grok
scripts/pair/grok-task.sh resume RUN замечания.md  # вернуть в ту же сессию
scripts/pair/grok-task.sh diff RUN                 # что именно он изменил
scripts/pair/grok-task.sh apply RUN                # принять: в рабочее дерево, без коммита
scripts/pair/grok-task.sh clean RUN                # убрать копию
```

Цикл: `start` → `check` → ревью → `resume` с дословным выводом проверок и
замечаниями → снова `check` → `apply` либо отказ. Не больше трёх раундов на
задачу: если за три раунда работа не принята, задача возвращается шефу.

## Кто что делает

| | Grok, стажёр | Claude, шеф |
|---|---|---|
| читать, искать, править файлы в своей копии | да | да |
| терминал: сборка, тесты, rustfmt, ворота | **нет** | да, в копии стажёра |
| числа тестов в отчёте | не приводит | из своего прогона |
| решение принять или вернуть | нет | да |
| попадание в рабочее дерево владельца | нет | `apply`, без коммита |

Отчёт стажёра — JSON по схеме [`report-schema.json`](../../scripts/pair/report-schema.json):
что изменено и зачем, кого затрагивает изменение (найдено поиском), какие
тесты «пройти неправильно» добавлены, какие проверки шефу запустить, что не
сделано. Утверждения стажёра шеф сверяет с кодом, а не принимает на веру.

## Почему у стажёра нет терминала

Всё ниже проверено на одноразовом репозитории, по факту на диске, до того как
на это положились.

| механизм Grok | держит? |
|---|---|
| запрет `git commit` в режиме без подтверждений | ✓ отказ, коммитов не прибавилось |
| явный запрет внутри цепочки `cat x; git commit …` | ✓ отказ |
| запись файлов вне каталога — `../x` и абсолютный путь | ✓ отказ |
| общий запрет терминала `--deny Bash` | ✓ отказ; работа продолжается файловыми инструментами |
| **разрешение** одной команды оболочки | ✗ проверяется только начало: с разрешённым `cat` команды `cat x; touch ../y` и `cat x && touch ../y` выполнились целиком |
| песочница `--sandbox workspace` на macOS | ✗ `touch ../y` и `curl` прошли |

Список разрешённых команд — не граница: достаточно одной разрешённой команды и
точки с запятой. Поэтому терминал запрещён целиком. Стажёр читает, ищет и
правит файлы только внутри своей копии; собирает и проверяет шеф.

Сверху ещё два слоя, не зависящих от Grok:

- **копия вне проекта** — git worktree во временном каталоге (`$TMPDIR/sciwitch-pair`);
- **растяжка** — отпечаток настоящего рабочего дерева до и после каждого
  раунда. Изменилось — раунд помечается, `apply` его не примет. Не правьте
  основное дерево, пока идёт раунд Grok: растяжка не отличит вашу правку от
  побега стажёра и отбракует раунд. Это ложная тревога в безопасную сторону.

`apply` отказывает ещё в одном случае: если файл, который меняет патч,
изменился в рабочем дереве после старта задачи. Остальные файлы могут жить
своей жизнью.

## Пределы

Все явные и переопределяются через окружение:

| переменная | по умолчанию | что ограничивает |
|---|---|---|
| `PAIR_MAX_TURNS` | 80 | шагов агента за раунд |
| `PAIR_MAX_ROUNDS` | 3 | раундов на задачу, считая первый |
| `SCIWITCH_PAIR_HOME` | `$TMPDIR/sciwitch-pair` | где лежат запуски |
| `GROK_BIN` | `~/.grok/bin/grok` | исполняемый файл Grok |

Отказы проверены вручную: повторное `apply` поверх изменённого файла и
четвёртый раунд сверх предела завершаются с кодом 1; растяжка замечает новый
файл в рабочем дереве.

## Известные границы

- Стажёр не может собрать код и увидеть ошибку компиляции сам. Её увидит шеф
  на `check`, и это лишний раунд. Цена безопасности, а не недосмотр.
- Схема отчёта у Grok действует на каждое сообщение, не только на последнее,
  поэтому ответ — цепочка JSON-объектов. Скрипт берёт последний и называет его
  отчётом только если запуск завершился штатно (`stopReason: end_turn`).
- Проверки уровня Grok (права, песочница) могут измениться с его обновлением.
  Таблица выше верна для `grok 1.0.41`. После обновления её стоит перепроверить
  на одноразовом репозитории, прежде чем на неё полагаться.

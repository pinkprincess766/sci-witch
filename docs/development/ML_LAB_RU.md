# Лаборатория измерений sci-witch

Практический документ: как запустить измерения, что означает каждое число и что лаборатория показала на первом прогоне. Теоретический протокол и ворота допуска — в [ML_RESEARCH_RU.md](ML_RESEARCH_RU.md); этот файл описывает то, что **уже работает**.

Главное свойство: лаборатория ничего не встраивает в приложение. Она читает `sciwhisper-core` через публичный API (`interpret`, `InterpretationResult`, `Node`, `Domain`, `alternatives`) и измеряет его как есть.

## 1. Контур

```
research/data/dev-seed-v2.jsonl        текущий версионированный dev-корпус
        ↓  schema.rs        строгая загрузка, отказ вместо тихой подмены
        ↓  canonical.rs     канонический AST v1 + отдельное действие RAW
        ↓  candidates.rs    кандидаты из настоящего core + RAW
        ↓  evaluate.rs      детерминированный выбор и решение insert/abstain
        ↓  oracle.rs        error decomposition, oracle replacement, isolation
        ↓  metrics.rs       доли, CI, recall@K, severity
        ↓  report.rs        JSON-отчёт + компактная таблица
research/results/deterministic-v4.json
```

## 2. Команды

```bash
cargo run -p sciwhisper-eval -- validate-dataset --dataset research/data/dev-seed-v2.jsonl
# старые отчёты не перезаписываются: номер — версия опубликованного результата
cargo run -p sciwhisper-eval -- evaluate --dataset research/data/dev-seed-v2.jsonl --output research/results/deterministic-v4.json
cargo run -p sciwhisper-eval -- recall-curve --dataset research/data/dev-seed-v2.jsonl
cargo run -p sciwhisper-eval -- inspect-errors --report research/results/deterministic-v4.json
cargo run -p sciwhisper-eval -- compare --baseline research/results/deterministic-v2.json --candidate research/results/deterministic-v4.json
```

Заполнение голосового корпуса из записей — отдельная команда приложения, а не лаборатории:

```bash
cargo run -p sciwhisper-cli -- ingest --manifest research/data/voice-v1.manifest.jsonl \
  --output research/data/voice-v1.jsonl [--describe-only]
```

Полезные ключи `evaluate`: `--split train|validation|dev_holdout|all`, `--k`, `--threshold`, `--renderer`, `--policy auto|auto-then-explicit`.

Отчёт воспроизводим: два запуска одной конфигурации дают побайтово одинаковый JSON, кроме блока `timing`. Абсолютных путей в отчёте нет — хранится только имя файла корпуса и его SHA-256.

## 3. Что означают метрики

| Метрика | Что считает |
|---|---|
| `ast_exact_match` | выбранный ответ совпал с gold **до** решения вставлять |
| `pre_insertion_end_to_end_exact_match` | итоговая полезная нагрузка, отдельно для Unicode, LaTeX, OMML |
| `auto_insert_exact_match` | то же, но только среди автоматически вставленных |
| `coverage` | доля фраз, где система решилась вставить |
| `overall_exact_match` | по всем примерам; отказ на научной фразе — ошибка, `RAW` на обычной речи — успех |
| `candidate_recall_at_k` | правильный ответ вообще присутствует среди первых `K` кандидатов |
| `routing_accuracy` | только там, где научный домен был задуман |
| `raw_accuracy` | обычная речь осталась словами |
| `false_scientific_rewrite_rate` | обычная речь самовольно стала формулой |
| `false_abstention_rate` | научная фраза осталась текстом |
| `ast_validity` | вставленный AST удовлетворяет структурным инвариантам ядра |

**`pre_insertion_` — не оговорка.** Протокол определяет `EndToEndExactMatch` включая вставку в приложение. Лаборатория не открывает Word и не трогает буфер обмена, поэтому она измеряет payload **до** вставки в ОС и называется соответственно. Путь Word COM остаётся непроверенным.

Доверительные интервалы: для долей — интервал Уилсона (при таких маленьких счётчиках он корректнее нормального приближения), для headline-метрики дополнительно детерминированный bootstrap с фиксированным seed. При **нуле наблюдений** публикуется точная односторонняя верхняя граница `1 − 0.05^(1/n)`: наблюдаемый ноль не является доказанным нулём.

## 4. Разложение ошибок

Каждая неуспешная запись получает **одну** первую блокирующую категорию в фиксированном порядке:

```
dataset-invalid → ASR-first → router-first → candidate-first → rank-first → decision-first → render-first
```

На текстовом корпусе `ASR-first` — **`N/A`**: ни одна запись не несёт ASR-гипотезы, поэтому отказ парсера физически не может быть записан на распознавание. Отчёт сообщает это явным примечанием и полем `asr_first_applicable_examples: 0`.

`render-first` проверяется только там, где корпус несёт зафиксированный автором ожидаемый вывод (`expected_render`). Там, где он есть, он **побеждает** вывод renderer при сравнении — иначе renderer определял бы собственную правильность.

## 5. Два вида oracle

Их нельзя путать и нельзя складывать.

* **Oracle replacement** — идеальным делается один компонент внутри полного конвейера. Отвечает на продуктовый вопрос: что выгоднее чинить.
* **Component isolation** — компонент получает идеальные входы от всех предыдущих стадий. Отвечает на лабораторный вопрос: насколько хорош сам алгоритм.

Прирост от oracle-замен не аддитивен: компоненты взаимодействуют, и отчёт это прямо пишет.

Единственное место во всём crate, где gold попадает в набор кандидатов, — функция `oracle_candidates`, и она так и называется. Обычный генератор кандидатов физически не может увидеть правильный ответ: его нет в сигнатуре.

## 7. Bottleneck первого прогона: маршрутизация

Единственная oracle-замена с ненулевым приростом — **домен**. Восемь из двенадцати ошибок — `router-first`.

Механизм виден в `inspect-errors`. `detect_domain` начисляет очки по ключевым словам и названиям элементов, а при нулевом счёте по умолчанию выбирает математику. Поэтому тривиальные названия веществ без предметного слова уходят в математический парсер и не разбираются:

```
вода            → mathematics → отказ (правильно: H₂O)
метан           → mathematics → отказ
аммиак          → mathematics → отказ
поваренная соль → mathematics → отказ
едкий натр      → mathematics → отказ
медный купорос  → mathematics → отказ
```

Физика ошибается симметрично: «синус трёх метров» набирает 3 очка за «синус» против 2 за единицу и уходит в чистую математику, где единиц нет; «дельта же равно минус эн эф е» уходит в химию из-за слова «дельта».

При лабораторной политике `auto_then_explicit` (четыре прохода вместо одного) overall поднимается до 108/113, а `router-first` падает с 8 до 1 — но появляется одна ошибка `S2`: для «дельта же равно минус эн эф е» первым идёт кандидат из математического прохода с неправильным регистром (`ΔG = −nfe`), а правильный физический (`ΔG = −nFE`) стоит вторым. Это одновременно подтверждает диагноз и показывает цену наивного расширения набора кандидатов.

Оставшиеся ошибки:

* `candidate-first` (3) — феррит бария (нет в онтологии), «кельвинов» и «паскалей» (нет в списке произносимых форм единиц);
* `decision-first` (1) — «корень из икс плюс один» разбирается правильно и стоит первым, но предупреждение о неоднозначной границе корня понижает confidence до 0.7, и порог 0.9 превращает верный разбор в отказ.

**Грамматика в этой задаче намеренно не чинилась.** Отчёт показывает провалы как есть.

## 8. Safety

Все 12 ошибок — класса `S1` (безопасный отказ). Классов `S2`, `S3`, `S4` не наблюдалось.

Ни одна из 28 обычных фраз — включая «предел терпения», «производная была опубликована», «вода закипела в чайнике», «серная кислота хранится в лаборатории» — не была переписана в формулу. Это `0/28`, то есть верхняя 95% граница вероятности ≈ `0.10`. **Ноль наблюдений не означает нулевую вероятность**, и отчёт печатает границу рядом с нулём.

Обратная сторона: `coverage` 64.6% и `false abstention` 14.1%. Система безопасна за счёт того, что часто молчит.

### Ничья между грамматиками

Грамматика физики — надмножество математической, поэтому «икс в квадрате» разбирается обеими и в обеих набирает ноль очков. Первая версия `route()` брала на ничьей последний максимум (`max_by_key`), и восемь чисто математических записей получали ярлык `physics` при полностью правильном AST. Ошибкой в `overall` это не было — метрика сравнивает ответ, а не ярлык, — но домен решает, как результат отрисуется и какие предупреждения к нему применимы, так что молчаливо неверный ярлык это дефект. На равных уликах теперь выигрывает более узкое чтение; физика должна быть заслужена единицей, величиной или константой в самих словах. Проверяется в `acceptance.rs`.

### Что осталось (2 из 113)

| Запись | Split | Стадия | Severity | Что происходит |
|---|---|---|---|---|
| `chem-ferrite-ba-001-a` | `dev_holdout` | candidate-first | S1 | «феррит бария» → BaFe₁₂O₁₉ нет в онтологии, слова сохранены |
| `math-root-atom-001-a` | `dev_holdout` | decision-first | S1 | «корень из икс плюс один» разбирается верно, но предупреждение о границе корня опускает confidence до 0.7 |

Обе — в `dev_holdout`, обе класса `S1` (безопасный отказ, ничего не выдумано), и обе **намеренно не чинились**. Правка словаря или порога по записи, которую видно в holdout, тратит holdout: после этого его число перестаёт быть оценкой обобщения. «Кельвинов» и «паскалей» из v1 чинились по-другому — не по этим двум записям, а полной парадигмой для всех 22 единиц сразу, с тестом, который не пускает в `units.yaml` новую единицу без её склонения.

## 10. Обучаемый reranker

Не построен, и это решение по данным, а не по вкусу. Полное обоснование — в [`research/reranker/README_RU.md`](../../research/reranker/README_RU.md).

Коротко: лишь **1** пример из 113 предлагает больше одного различного научного AST, и в нём же правильный ответ стоит не первым. Ранжировать почти нечего. Модель, обученная здесь, выучила бы «единственный AST против RAW» и показала бы ~99% за решение другой задачи. Порог допуска (50 неоднозначных примеров, 20 с правильным ответом не первым, по 10 в train и validation) зафиксирован в коде и пересчитывается каждым запуском — поле `metrics.reranker_readiness` в отчёте.

## 11. Расстояние между интерпретациями

До сих пор лаборатория умела сказать, **совпал** ли ответ с корпусом, и — через
`classify_severity` — **какого рода** ошибка. Ни то ни другое не говорит, насколько
далеко ответ уехал: одно расходящееся поле и двенадцать попадали в один класс, а
`H₂O → H₂O₂` стоило ровно столько же, сколько `H₂O → D₂O`.

[`distance.rs`](../../crates/sciwhisper-eval/src/distance.rs) — взвешенное
дерево-редакционное расстояние (Zhang–Shasha) поверх типизированного AST. Веса лежат в
[`ast-distance-v1.json`](../../research/schema/ast-distance-v1.json): то, что этот проект
считает серьёзным изменением, стало данными с версией, а не константами в Rust.

**Это метрика, и это проверяется.** Несимметричные веса рассматривались и отклонены:
`d(a,b) ≠ d(b,a)` превратило бы это в квазиметрику, шары перестали бы быть шарами, а любая
позднейшая кластеризация или поиск ближайших соседей молча сломались бы. Нужная научная
асимметрия — коэффициент дороже скобки — выражается **симметричными весами по полям**,
что ничего не стоит и сохраняет аксиомы.

Аксиомы не только обоснованы в комментарии, но и проверены: на всех парах и всех тройках
из 18 настоящих интерпретаций корпуса. Загрузчик отказывается принять файл весов, который
нарушил бы метрику.

Ключ — `Вариант.поле`, а не голое имя поля. `kind` внутри `Group` это круглая скобка
против квадратной, а внутри `Function` — синус против косинуса; классификатор, видевший
только имя поля, обязан был оценивать их одинаково.

В отчёте появился блок `ast_distance` и поле `ast_distance` у каждой ошибки. На текущем
корпусе `comparable_errors: 0`: единственная оставшаяся ошибка — отказ, а между `RAW` и AST
дерева для правки нет, только другое решение. Это записано как `incomparable_errors: 1`,
а не как ноль расстояния.

### Устойчивость: инвариантность и эквивариантность

[`stability.rs`](../../crates/sciwhisper-eval/src/stability.rs) проверяет две стороны:

* **инвариантность** — регистр, ё/е, лишние пробелы прогоняются по всему корпусу (больше
  200 проверок) и обязаны дать `d_sci = 0` **точно**. Плюс парафразы: 10 семейств корпуса
  задают один AST на несколько формулировок, и декодер обязан соглашаться.
* **эквивариантность** — сформулирована как **порядок**, а не величина. Утверждение о
  величине лишь прочитало бы обратно веса из этого же проекта; порядок говорит о
  декодере: «железа два» → «железа три» обязано лечь ближе, чем несвязанное вещество.

Константа Липшица из ADR-0003 отброшена: `d_X` на русских высказываниях не определена,
поэтому `L` подбиралась бы на глаз и была бы нефальсифицируема.

### Что нашла эта проверка

**Лаборатория и приложение выполняют разные декодеры.** `candidates.rs` вызывает
`interpret`; `pipeline.rs` — тот код, который запускает пользователь, — вызывает
`interpret_utterance` в режиме `MixedText`, заменяющий доказанные фрагменты **внутри**
предложения. У замены фрагментов в лаборатории аналога нет вообще.

Версия корпуса 2 фиксирует различие политик явно. Для фразы «серная кислота
хранится в лаборатории» узкий лабораторный разбор обязан выбрать `RAW`, а
пользовательский `MixedText` — показать «H₂SO₄ хранится в лаборатории». Ожидаемый
смешанный документ записан отдельно и не выдаётся за `target_ast` всего предложения.

Отчёт поэтому содержит две независимые проверки. `mixed_exact_match` прогоняет через
пользовательский путь **все 113 записей** и получает 113/113. Доля ложных переписываний
считается только по 28 RAW-записям, которые действительно должны остаться неизменными,
и равна 0/28. Узкий парсер отдельно даёт 0/29. Обе нулевые оценки имеют широкую верхнюю
95% границу и не заменяют проверку на живом frozen-корпусе.

## 12. Порог вставки: risk–coverage и калибровка

Порог `0.9` был выставлен рукой и до сих пор не имел обоснования. Теперь он
не защищается, а **измеряется**: отчёт содержит блок `selective_prediction`
с кривой по всем порогам и с калибровкой шкалы уверенности.

```
порог   покрытие   риск     точность
0.00     85/113     1/85    112/113
0.70     85/113     1/85    112/113
0.80     83/113     0/83    112/113
0.90     83/113     0/83    112/113   ← настроенный
1.00      0/113       —      29/113
```

Читается так: между 0.0 и 0.95 точность **не меняется вовсе**. Два лишних
ответа при 0.7 — один верный, один нет. По точности это ничья; по
таксономии severity — нет, потому что уверенная ошибка хуже безопасного
молчания.

Поэтому `no_worse_than_configured` требует не уступать **по всем трём**
числам сразу: покрытию, точности и риску. Без третьего условия список
рекомендовал порог `0.0` — «отвечать всегда», — и это был дефект в первой
версии этого модуля, а не находка.

### Калибровка

```
уверенность 0.70: 2 примера,  верно 1/2   (слишком мало, чтобы читать как свидетельство)
уверенность 0.95: 83 примера, верно 83/83
Brier 0.0093 · ECE 0.0535 · ошибок среди отвеченного 1
```

Оценка приняла **два** различных значения, а не четыре, и на одном из них
два примера. Хороший Brier здесь ничего не значит: почти постоянная шкала
всегда выглядит откалиброванной.

### Вердикт

> порог нельзя выбрать по данным: ошибок среди отвеченного 1, нужно не
> менее 20.

Это не отговорка: при одной ошибке любые два порога различаются в пределах
шума, и «лучший» будет выбран случайно. Но число ошибок само по себе не может
быть воротами `threshold-chosen-from-data`: оно не доказывает, что порог выбран
по заранее заданной процедуре, и большое число ошибок не должно быть условием
выпуска. Поэтому risk–coverage и калибровка остаются диагностикой; отдельные
ворота появятся только вместе с предзарегистрированным правилом выбора порога
на реальном validation-корпусе.

**Что отсюда следует для ML.** Подгонять здесь нечего, и дело не в методе:
корпус исчерпал разрешающую способность. Все шесть oracle-замен дают одно
число (112), маршрутизатор изолированно 84/84, полнота кандидатов 113/113.
Пока не появятся записи, никакая модель не может показать улучшение —
и, что важнее, не может показать ухудшение.

## 13. Ворота допуска (0.5)

Требования к публичной версии перестали быть строчками в чек-листе, которые человек
отмечает галочкой. Они лежат в [`research/schema/release-gates-v1.json`](../../research/schema/release-gates-v1.json)
и проверяются программой:

```bash
cargo run -p sciwhisper-eval -- gate --report research/results/deterministic-v4.json
```

Три свойства дают воротам зубы:

**Судят по границе, а не по точечной оценке.** 90% на двадцати примерах — не 90%. Каждые
пропорциональные ворота читают тот конец доверительного интервала, который может
опозорить: нижнюю границу для точности, верхнюю — для доли отказов.

Это не теория. На нынешнем корпусе `ast_validity` наблюдается как **83/83 = 100%**, а
нижняя граница 95% CI — **0.956**. Ворота «структурная валидность ≥ 0.99» не проходят, и
правильно: 83 примера не могут подтвердить 99%.

**Невыполненное предусловие — это не «пройдено».** Ворота о живой речи, посчитанные на
письменном корпусе, отвечают «не измеримо» и блокируют выпуск ровно так же, как провал.
Иначе 98.2% на рукописных предложениях незаметно превратились бы в утверждение о
микрофонах.

**Ноль судится по верхней границе.** Ноль ложных переписываний из 28 предложений совместим
с истинной долей 10%. Ворота требуют верхнюю границу ≤ 0.02, а это уже вопрос размера
выборки, а не удачи.

Текущее состояние на `dev-seed-v2`:

```
НЕ ИЗМЕРИМО  end-to-end-accuracy      0 записей provenance=real_audio, нужно 200
НЕ ИЗМЕРИМО  shipped-end-to-end-accuracy 0 записей provenance=real_audio, нужно 200
НЕ ИЗМЕРИМО  auto-insert-precision    0 записей provenance=real_audio, нужно 200
НЕ ИЗМЕРИМО  no-dangerous-rewrites-shipped 0 записей provenance=real_audio, нужно 150
НЕ ИЗМЕРИМО  no-dangerous-rewrites-parser 0 записей provenance=real_audio, нужно 150
НЕ ИЗМЕРИМО  no-s4-errors             0 записей provenance=real_audio, нужно 150
НЕ ИЗМЕРИМО  structural-validity      frozen test не запечатан
ПРОЙДЕНО     split-hygiene            ни семейство, ни диктор не пересекают split
```

Семь из восьми ворот сейчас не измеримы. Их закрывают **записи и заранее
запечатанный тест, а не код**.

### Frozen test

Корпус запечатывается один раз, до того как числа известны:

```bash
cargo run -p sciwhisper-eval -- seal --dataset research/data/voice-frozen-v1.jsonl \
  --out research/schema/frozen-test-seal.json --release 0.5 --date 2026-11-01
```

Печать называет корпус по SHA-256. Отчёт, полученный на другом файле, ворота не пройдёт —
редактирование после запечатывания видно. Перепечатывание не предусмотрено: тест, который
можно запечатать заново после того, как результат стал известен, — это тест, который
подгоняют. Корпус с утечкой split запечатать нельзя вовсе, иначе утечка была бы
зафиксирована навсегда.

## 14. Что здесь честно не измерено

* **Реальных голосов нет.** Корпус текстовый, `provenance: handcrafted_text` у всех 113 записей. С 0.3 схема корпуса умеет держать записи (`dataset_schema_version: 2`: файл, sha256, длительность, микрофон, обстановка, SNR, согласие), а `sciwhisper-cli ingest` заполняет измеримую часть из самих файлов — но **записей по-прежнему нет**, и придумать их нельзя. Протокол сбора: [`research/data/VOICE_CORPUS_RU.md`](../../research/data/VOICE_CORPUS_RU.md).
* **Точность ASR не измерена.** Ни одной ASR-гипотезы в корпусе, поэтому `ASR-first` = `N/A`, а не 0%. Разложение по стадиям и `oracle transcript` начнут давать число в тот день, когда в корпусе появятся записи; кода для этого больше не требуется.
* **`confidence` ядра — не вероятность.** Это уровни детерминированного разбора (1.0 / 0.95 / 0.7 / 0.0). Risk–coverage, Brier и ECE теперь считаются как диагностика этой шкалы, но две занятые точки и одна ошибка не позволяют объявить её калиброванной или выбрать порог по данным.
* **Вставка в Word не проверена.** Измерение заканчивается до OS insertion.
* **`dev_holdout` — не frozen test.** Он открывался при отладке лаборатории; настоящий frozen test заводится вместе с реальным голосовым корпусом.
* **Корпус маленький.** 113 записей, 103 семейства. Все выводы читать вместе с доверительными интервалами.
* **Transformer не заслужил права на интеграцию.** До него не дошли даже логистический и MLP baseline, и bottleneck сейчас вообще не в ранжировании.

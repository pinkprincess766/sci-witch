# Лаборатория измерений sci-witch

Практический документ: как запустить измерения, что означает каждое число и что лаборатория показала на первом прогоне. Теоретический протокол и ворота допуска — в [ML_RESEARCH_RU.md](ML_RESEARCH_RU.md); этот файл описывает то, что **уже работает**.

Главное свойство: лаборатория ничего не встраивает в приложение. Она читает `sciwhisper-core` через публичный API (`interpret`, `InterpretationResult`, `Node`, `Domain`, `alternatives`) и измеряет его как есть.

## 1. Контур

```
research/data/dev-seed-v1.jsonl        версионированный корпус (schema 1)
        ↓  schema.rs        строгая загрузка, отказ вместо тихой подмены
        ↓  canonical.rs     канонический AST v1 + отдельное действие RAW
        ↓  candidates.rs    кандидаты из настоящего core + RAW
        ↓  evaluate.rs      детерминированный выбор и решение insert/abstain
        ↓  oracle.rs        error decomposition, oracle replacement, isolation
        ↓  metrics.rs       доли, CI, recall@K, severity
        ↓  report.rs        JSON-отчёт + компактная таблица
research/results/deterministic-v1.json
```

## 2. Команды

```bash
cargo run -p sciwhisper-eval -- validate-dataset --dataset research/data/dev-seed-v1.jsonl
cargo run -p sciwhisper-eval -- evaluate --dataset research/data/dev-seed-v1.jsonl --output research/results/deterministic-v1.json
cargo run -p sciwhisper-eval -- recall-curve --dataset research/data/dev-seed-v1.jsonl
cargo run -p sciwhisper-eval -- inspect-errors --report research/results/deterministic-v1.json --stage router-first
cargo run -p sciwhisper-eval -- compare --baseline a.json --candidate b.json
```

Полезные ключи `evaluate`: `--split train|validation|dev_holdout|all`, `--k`, `--threshold`, `--renderer`, `--policy auto|auto-then-explicit`.

Отчёт воспроизводим: два запуска одной конфигурации дают побайтово одинаковый JSON, кроме блока `timing`. Абсолютных путей в отчёте нет — хранится только имя файла корпуса и его SHA-256.

## 3. Что означают метрики

| Метрика | Что считает |
|---|---|
| `ast_exact_match` | выбранный ответ совпал с gold **до** решения вставлять |
| `pre_insertion_end_to_end_exact_match` | итоговая полезная нагрузка, отдельно для Unicode, LaTeX, OMML |
| `auto_insert_exact_match` | то же, но только среди автоматически вставленных |
| `coverage` | доля фраз, где система решилась вставить |
| `overall_exact_match` | по всем примерам; отказ на научной фразе — ошибка, `RAW` на обычной речи — успех |
| `candidate_recall_at_k` | правильный ответ вообще присутствует среди первых `K` кандидатов |
| `routing_accuracy` | только там, где научный домен был задуман |
| `raw_accuracy` | обычная речь осталась словами |
| `false_scientific_rewrite_rate` | обычная речь самовольно стала формулой |
| `false_abstention_rate` | научная фраза осталась текстом |
| `ast_validity` | вставленный AST удовлетворяет структурным инвариантам ядра |

**`pre_insertion_` — не оговорка.** Протокол определяет `EndToEndExactMatch` включая вставку в приложение. Лаборатория не открывает Word и не трогает буфер обмена, поэтому она измеряет payload **до** вставки в ОС и называется соответственно. Путь Word COM остаётся непроверенным.

Доверительные интервалы: для долей — интервал Уилсона (при таких маленьких счётчиках он корректнее нормального приближения), для headline-метрики дополнительно детерминированный bootstrap с фиксированным seed. При **нуле наблюдений** публикуется точная односторонняя верхняя граница `1 − 0.05^(1/n)`: наблюдаемый ноль не является доказанным нулём.

## 4. Разложение ошибок

Каждая неуспешная запись получает **одну** первую блокирующую категорию в фиксированном порядке:

```
dataset-invalid → ASR-first → router-first → candidate-first → rank-first → decision-first → render-first
```

На текстовом корпусе `ASR-first` — **`N/A`**: ни одна запись не несёт ASR-гипотезы, поэтому отказ парсера физически не может быть записан на распознавание. Отчёт сообщает это явным примечанием и полем `asr_first_applicable_examples: 0`.

`render-first` проверяется только там, где корпус несёт зафиксированный автором ожидаемый вывод (`expected_render`). Там, где он есть, он **побеждает** вывод renderer при сравнении — иначе renderer определял бы собственную правильность.

## 5. Два вида oracle

Их нельзя путать и нельзя складывать.

* **Oracle replacement** — идеальным делается один компонент внутри полного конвейера. Отвечает на продуктовый вопрос: что выгоднее чинить.
* **Component isolation** — компонент получает идеальные входы от всех предыдущих стадий. Отвечает на лабораторный вопрос: насколько хорош сам алгоритм.

Прирост от oracle-замен не аддитивен: компоненты взаимодействуют, и отчёт это прямо пишет.

Единственное место во всём crate, где gold попадает в набор кандидатов, — функция `oracle_candidates`, и она так и называется. Обычный генератор кандидатов физически не может увидеть правильный ответ: его нет в сигнатуре.

## 7. Bottleneck: маршрутизация

Единственная oracle-замена с ненулевым приростом — **домен**. Восемь из двенадцати ошибок — `router-first`.

Механизм виден в `inspect-errors`. `detect_domain` начисляет очки по ключевым словам и названиям элементов, а при нулевом счёте по умолчанию выбирает математику. Поэтому тривиальные названия веществ без предметного слова уходят в математический парсер и не разбираются:

```
вода            → mathematics → отказ (правильно: H₂O)
метан           → mathematics → отказ
аммиак          → mathematics → отказ
поваренная соль → mathematics → отказ
едкий натр      → mathematics → отказ
медный купорос  → mathematics → отказ
```

Физика ошибается симметрично: «синус трёх метров» набирает 3 очка за «синус» против 2 за единицу и уходит в чистую математику, где единиц нет; «дельта же равно минус эн эф е» уходит в химию из-за слова «дельта».

При лабораторной политике `auto_then_explicit` (четыре прохода вместо одного) overall поднимается до 108/113, а `router-first` падает с 8 до 1 — но появляется одна ошибка `S2`: для «дельта же равно минус эн эф е» первым идёт кандидат из математического прохода с неправильным регистром (`ΔG = −nfe`), а правильный физический (`ΔG = −nFE`) стоит вторым. Это одновременно подтверждает диагноз и показывает цену наивного расширения набора кандидатов.

Оставшиеся ошибки:

* `candidate-first` (3) — феррит бария (нет в онтологии), «кельвинов» и «паскалей» (нет в списке произносимых форм единиц);
* `decision-first` (1) — «корень из икс плюс один» разбирается правильно и стоит первым, но предупреждение о неоднозначной границе корня понижает confidence до 0.7, и порог 0.9 превращает верный разбор в отказ.

**Грамматика в этой задаче намеренно не чинилась.** Отчёт показывает провалы как есть.

## 8. Safety

Все 12 ошибок — класса `S1` (безопасный отказ). Классов `S2`, `S3`, `S4` не наблюдалось.

Ни одна из 28 обычных фраз — включая «предел терпения», «производная была опубликована», «вода закипела в чайнике», «серная кислота хранится в лаборатории» — не была переписана в формулу. Это `0/28`, то есть верхняя 95% граница вероятности ≈ `0.10`. **Ноль наблюдений не означает нулевую вероятность**, и отчёт печатает границу рядом с нулём.

Обратная сторона: `coverage` 64.6% и `false abstention` 14.1%. Система безопасна за счёт того, что часто молчит.

## 9. Обучаемый reranker

Не построен, и это решение по данным, а не по вкусу. Полное обоснование — в [`research/reranker/README_RU.md`](../../research/reranker/README_RU.md).

Коротко: **0** примеров из 113 предлагают больше одного различного научного AST, и лишь **1** содержит правильный ответ не на первом месте. Ранжировать нечего. Модель, обученная здесь, выучила бы «единственный AST против RAW» и показала бы ~99% за решение другой задачи. Порог допуска (50 неоднозначных примеров, 20 с правильным ответом не первым, по 10 в train и validation) зафиксирован в коде и пересчитывается каждым запуском — поле `metrics.reranker_readiness` в отчёте.

## 10. Что здесь честно не измерено

* **Реальных голосов нет.** Корпус текстовый, `provenance: handcrafted_text` у всех 113 записей.
* **Точность ASR не измерена.** Ни одной ASR-гипотезы в корпусе, поэтому `ASR-first` = `N/A`, а не 0%.
* **`confidence` ядра — не вероятность.** Это уровни детерминированного разбора (1.0 / 0.95 / 0.7 / 0.0). Ни одна метрика не обращается с ними как с калиброванной вероятностью; калибровка, Brier, ECE и risk–coverage не считались.
* **Вставка в Word не проверена.** Измерение заканчивается до OS insertion.
* **`dev_holdout` — не frozen test.** Он открывался при отладке лаборатории; настоящий frozen test заводится вместе с реальным голосовым корпусом.
* **Корпус маленький.** 113 записей, 103 семейства. Все выводы читать вместе с доверительными интервалами.
* **Transformer не заслужил права на интеграцию.** До него не дошли даже логистический и MLP baseline, и bottleneck сейчас вообще не в ранжировании.

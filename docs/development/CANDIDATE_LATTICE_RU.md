# Candidate Lattice v1

`crates/sciwhisper-core/src/lattice.rs`

## Зачем

`interpret` отвечает одним разбором, `interpret_utterance` — одним документом.
Это **решения**. Решётка отвечает на другой вопрос: *чем ещё это могло быть?*
Она возвращает типизированный, упорядоченный, дедуплицированный набор прочтений,
каждое — с причиной своего появления, чтобы позже, на настоящих данных, можно
было обучить ранжировщик, а не подгонять его под первую догадку парсера.

Решётка ничего не вставляет. Ни один код, который выполняется у пользователя, её
не вызывает — проверено grep'ом по `sciwhisper-shell`, `sciwhisper-asr`,
`sciwhisper-cli`, `sciwhisper-update`. Её потребители: `sciwhisper-eval`
(`--policy lattice`, `dump-lattice`) и тесты.

## Что мерили до

На `dev-seed-v2` `CandidateRecall@K` равен 100% начиная с K=2. Такой корпус не
может ни поощрить более широкий набор кандидатов, ни наказать его: числа не
сдвинутся ни в какую сторону. Поэтому сначала был размечен
`research/data/ambiguous-v1.jsonl` — 58 записей, где задуманное прочтение
заведомо может не оказаться первым, — и только потом менялся алгоритм.

## Схема

```rust
pub struct Candidate {
    pub reading: Reading,          // Raw | Ast(Node)
    pub domain: Option<Domain>,    // None у Raw: он не продукт домена
    pub span: Span,                // байтовый диапазон в исходной расшифровке
    pub normalized: String,        // нормализованная форма этого диапазона
    pub origins: Vec<Origin>,      // причины появления, все
    pub warning_codes: Vec<String>,
    pub features: Features,        // детерминированные признаки
    pub whole_utterance: bool,
    pub rank: usize,
}
```

`origins` — вектор, а не одно значение, намеренно: одно и то же прочтение часто
достигается несколькими путями, и *какие пути согласились* — само по себе
свидетельство. При дедупликации причины сливаются, а не выбрасываются.

### Причины (`Origin`)

| причина | что делает | правит ли слова |
|---|---|---|
| `Raw` | слова как сказаны | нет |
| `WholeUtterance` | всё высказывание как одна конструкция, автоматическая маршрутизация | нет |
| `ForcedDomain(d)` | то же с принудительным доменом | нет |
| `GrammarAlternative` | второе прочтение, которое предлагает сама грамматика (радикал без «конец корня») | нет |
| `MixedDocument` | документ смешанного режима: проза сохранена, доказанные участки заменены | нет |
| `MaximalSpan` | самый длинный доказанный научный участок, вынутый из предложения | нет |
| `BridgeWordsDropped(words)` | убраны связки и слова-паразиты; **какие именно — перечислено** | да |
| `ProductClauseRotated` | вынесенное вперёд «с образованием Z» возвращено в конец | да |
| `SelfCorrection` | применена собственная поправка говорящего | да |
| `VowelRepair(swaps)` | заменена одна гласная; **какие слова — перечислено** | да |

### Признаки (`Features`)

Счётчики (с насыщением на 65535) и флаги, вычисленные из AST и разбора: `words`,
`covered_words`, `edited_words`, `warnings`, `ast_nodes`, `ast_depth`, `atoms`,
`text_nodes`, `balanced: Option<bool>`, `structurally_valid`, `parse_level`.

`atoms` учитывает индексы, группы и гидраты, но не коэффициенты реакции;
при переполнении точного подсчёта также насыщается. `balanced` проверяет
сохранение атомов во всех уравнениях документа, не химическую осуществимость
и не заряд; невозможность подсчёта даёт `None`, а не доказанный баланс.
`edited_words` при самокоррекции учитывает только отброшенные слова вне
выбранного участка: это не полное редакционное расстояние.

`parse_level` — **не вероятность**. Это структурный уровень парсера, то самое
число, которым всегда было `confidence`: оно принимает два значения, 0.95 для
чистого разбора и 0.7 для того, который грамматика сама назвала неоднозначным.
Ничто в решётке признаки между собой не взвешивает — это работа ранжировщика,
а ранжировщика здесь нет.

## Жёсткие пределы

| константа | значение | что ограничивает |
|---|---|---|
| `MAX_CANDIDATES` | 32 | размер решётки |
| `MAX_WORDS` | 400 | длина высказывания; дальше — только `RAW`, и `truncated = true` |
| `MAX_INPUT_BYTES` | 16384 | размер текста до нормализации и поиска; дальше исходный `RAW` |
| `MAX_ATTEMPTS` | 64 | вызовы парсера верхнего уровня; внутренний поиск участков ограничен отдельно |
| `MAX_ROTATIONS` | 4 | перестановки при вынесенном продукте |
| `MAX_REPAIRED_WORDS` | 2 | слов с починенной гласной |
| `MIN_REPAIR_WORD_CHARS` | 5 | короче — это уже другое слово, а не опечатка |
| `MAX_REPAIR_WORD_CHARS` | 64 | предел длины слова для перебора гласных |
| `REPAIR_VOWELS` | 4 пары | а↔о, е↔и |

Генераторы — фиксированный список, применяемый **только к исходному
высказыванию**; ни один не подаёт вход другому. Поэтому число кандидатов линейно
по числу генераторов, а `MAX_CANDIDATES` — гарантия, которая останется верной,
даже если это перестанет быть очевидным. Тест
`every_limit_holds_on_a_hostile_input` проверяет все пределы разом.

### Починка гласных — правило, а не словарь

Одна замена на слово, максимум два слова, только не на первой позиции, и
результат обязан **уже быть в лексиконе**. Это правило не может породить слово,
которого проект не знает. Открытый список опечаток рос бы без конца и начал бы
изобретать вещества.

Цена: правило не достаёт до многословных названий. «сернея кислота» не
чинится — «серная» само по себе не элемент, не анион и не название вещества,
им является только «серная кислота» целиком. Это записано как найденный предел,
а не закрыто расширением списка гласных задним числом.

## Правило безопасности: что может стоять впереди `RAW`

Решётка ставит `RAW` **первым**: сохранить слова — безопасный ответ, и никакое
усечение не должно суметь его убрать.

Гармонизатор в `sciwhisper-eval` переупорядочивает список, потому что
детерминированная базовая линия читает первую позицию как «что сделает система»,
а система предпочитает удачный разбор. Порядок там такой:

1. кандидаты прежней политики `auto`, в неизменном порядке;
2. `RAW`;
3. все дополнительные кандидаты решётки, включая принудительный домен,
   частичные прочтения (участок, вынутый из предложения;
   смешанный документ, внутри которого осталась проза) и прочтения, добытые
   удалением, перестановкой или починкой слов.

Первая версия этого адаптера держала в первой группе и частичные прочтения — на
том основании, что они ничего не правили. `FalseScientificRewriteRate` тут же
поднялся с 0/20 до 3/20: в предложении с веществом *всегда* есть какая-то
структура внутри. Отсюда флаг `whole_utterance`, который выставляют только
генераторы всего высказывания.

Самого флага `whole_utterance` недостаточно: принудительный домен тоже может
построить полное прочтение там, где `auto` отказался. Поэтому перед `RAW`
сохраняется именно прежний список `auto`, а не кандидаты с этим флагом.
Слияние причин появления кандидата не меняет его позицию. Усечение отчёта
учитывает фактический лимит генератора или отсечение по K, а не равенство размера K.

В oracle-экспериментах идеальный домен меняет только домен внутри выбранного
генератора. Политика решётки не подменяется одиночным разбором: иначе ошибка
выбора ошибочно превращалась бы в отсутствие кандидата.

Смысл третьей группы — и весь её риск — в том, что recall её видит, а
детерминированное решение выбрать из неё не может. Поэтому более широкая
решётка сама по себе не способна поднять долю опасных перезаписей. Обученный
позже ранжировщик может начать поднимать эти кандидаты — это будет измеренное
решение, и текущий отчёт будет его базовой линией.

## Как пользоваться

```bash
cargo run -p sciwhisper-eval -- evaluate \
  --dataset research/data/ambiguous-v1.jsonl --policy lattice \
  --output research/results/lattice-v1.json
```

```bash
cargo run -p sciwhisper-eval -- dump-lattice \
  --dataset research/data/ambiguous-v1.jsonl \
  --output research/results/ambiguous-v1-lattice.jsonl
```

`dump-lattice` пишет по одному JSON-объекту на запись: расшифровка, золотой
ответ, все кандидаты с причинами, признаками и предупреждениями. Это и есть файл,
на котором обучался бы ранжировщик, и причина, по которой кандидат вообще несёт
причины и признаки. В нём нет ни решения, ни модели.

Экспорт сохраняет также типизированный `ast`, подробные `origin_details`,
`split`, `provenance` и `speaker_id`. При обучении нельзя перемешивать строки
между исходными split или допускать утечку семей/дикторов.

Ранги в этом файле — **собственные ранги решётки**, где `RAW` первый. Гармонизатор
переупорядочивает список перед решением, поэтому поле называется
`gold_rank_in_lattice`, а не `gold_rank`: это разные числа, и читатель, который
их перепутает, неверно прочтёт оба.

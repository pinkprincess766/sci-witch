### 3А. Формальная грамматика устной математической и химической речи

**Цель.** Превратить рукописный рекурсивный спуск в явный, проверяемый математический объект: грамматику, свойства которой можно доказывать и измерять.

Что есть сейчас: `parser/math.rs` — рукописный токенизатор и рекурсивный спуск с уровнями приоритета (`parse_eq → parse_add → parse_mul → parse_unary → parse_juxt → parse_postfix → parse_atom`). `data/domains/*/grammar.yaml` — это **документация**, код её не загружает (`include_str!` подключает только `operators.yaml`, словари и aliases). Грамматика как объект нигде не существует.

**Задачи.**
- [x] Записать EBNF для математики и химии **по коду**, а не по желаемому поведению: [`docs/grammar/math.ebnf`](../grammar/math.ebnf), [`chem.ebnf`](../grammar/chem.ebnf). Каждое правило со ссылкой на функцию-парсер.
- [x] Классифицировать язык: построить FIRST/FOLLOW, проверить, LL(1) ли грамматика с «граничными командами» («начало дроби … конец дроби»). Где нет — найти конкретный конфликт и пример фразы. Гипотеза для проверки: граничные команды делают вложенные конструкции LL(1), а «естественные» (без границ) дают неоднозначность; `RootBinding` и `reparse_with` в `math.rs` — прямой её симптом.
  Сделано: [`docs/grammar/ANALYSIS_RU.md`](../grammar/ANALYSIS_RU.md) — таблицы FIRST/FOLLOW, список LL(1)-конфликтов с фразами и выводом компилятора, вердикт по гипотезе (подтверждена частично), ограничения анализа (числа — в сводке документа). Документы сверяет с кодом тест `crates/sciwhisper-core/tests/grammar_first_follow.rs`. Из этого пункта не сделано: руками доказанная однозначность подграммы с границами (она в следующем пункте).
- [ ] **Неоднозначность.** Неоднозначность КС-грамматики в общем случае неразрешима, поэтому доказать её отсутствие алгоритмом нельзя. Можно: (1) доказать однозначность для подграммы с граничными командами руками; (2) эмпирически искать неоднозначные предложения ограниченной длины перебором или генерацией.

  - дифференциальное тестирование: на корпусе и на сгенерированных из грамматики фразах сравнивать «принимает / не принимает» и AST с рукописным парсером; каждое расхождение — баг в одном из них;

  Почему Earley, а не CYK: CYK требует нормальной формы Хомского (дерево меняется, его нужно обратно преобразовывать), а Earley работает с произвольной КС-грамматикой. GLR рассмотреть в теории, реализовывать не обязательно.
- [ ] **PCFG.** Вероятности правил считать по MLE из gold-деревьев train (если gold AST однозначно отображается в вывод; если нет — inside-outside, но это сильно сложнее, **ЧЕРНОВИК**). Выход: `log P(дерево)` и перплексия грамматики на dev.

Формальная постановка: найти предложение языка грамматики на минимальном взвешенном редакционном расстоянии от транскрипта (классический error-correcting parsing, алгоритм Ахо–Петерсона 1972 для минимального расстояния; реализуется как Earley с операциями вставки/удаления/замены). ### 3Б. Rescoring N-best гипотез Whisper через грамматику

**Цель.** Проверить, помогает ли знание грамматики исправлять ошибки распознавания.

**Задачи.**
- [ ] **ЧЕРНОВИК: как получить N гипотез.** Сейчас приложение вызывает whisper.cpp CLI с `-otxt` (`whisper_cli.rs`) — это один лучший вариант. В CLI whisper.cpp есть `--best-of`, `--beam-size`, `-ojf` (полный JSON с вероятностями токенов), но списка N-best CLI не отдаёт (проверено по `examples/cli/cli.cpp`). Варианты: (a) K прогонов с температурой > 0 и разными seed; (b) привязки к whisper.cpp из Rust (например, crate `whisper-rs`) с доступом к декодеру; (c) патч whisper.cpp. Начать с (a) — дёшево, но гипотезы коррелированы.
- [ ] Для каждой гипотезы: ASR-оценка (сумма log-prob токенов из `-ojf`) + разбор (успех/неудача, `log P_PCFG`, число разборов) → комбинированный скор `λ·ASR + (1−λ)·grammar`. λ подбирать на dev по дикторам.

### 3Г. Корректность и верификация алгебраических частей (балансировка)

**Что в коде (проверено, `core/src/balance.rs`).** Матрица сохранения $A\in\mathbb Q^{r\times n}$ (строки — элементы и, если есть ненулевой заряд, заряд; столбцы — вещества, правая часть со знаком минус). RREF на дробях `i128` со всеми операциями через `checked_*`. Ответ возвращается только если свободный столбец ровно один (`let [free] = free_cols[..]`), ядро без нулей и одного знака. Затем минимальный целочисленный вектор (НОК знаменателей, деление на НОД) и отсечение коэффициентов больше 9999. В `experimental` подсчёт атомов тоже проверяется на переполнение (`atom_counts → Option`). Есть ручные доказательства в `FORMAL_GUARANTEES_RU.md` (черновик), property-based тестов нет: `proptest`/`quickcheck` в зависимостях отсутствуют.

**Математика, которую надо уметь доказать самому:**
- rank–nullity: $\dim\ker A = n - \operatorname{rank}A$. Балансировка единственна с точностью до масштаба ⇔ $\dim\ker A = 1$;
- ядро рациональной матрицы имеет базис из целых векторов; при $\dim\ker A=1$ существует единственный примитивный (НОД = 1) положительный вектор, если он вообще есть. Это и есть «минимальное целочисленное решение»;
- при $\dim\ker A \ge 2$ множество допустимых балансировок — пересечение ядра с положительным ортантом, то есть многогранный конус. «Минимальное» решение там не единственно: можно минимизировать сумму коэффициентов (целочисленное ЛП), можно говорить о базисе Гильберта конуса (есть готовые инструменты, например Normaliz или 4ti2). Химически это разные независимые реакции в одной записи. Сейчас код правильно воздерживается;
- Q против Z: нормальные формы Эрмита и Смита дают целочисленный базис ядра без дробей;
- рост чисел: безфракционное исключение Бареиса держит промежуточные значения равными минорам матрицы, а миноры ограничены неравенством Адамара. Отсюда можно вывести **априорное достаточное условие**, при котором `i128` гарантированно не переполнится (по максимуму числа атомов и размеру матрицы). Для текущего алгоритма на дробях промежуточное `checked_mul` в `checked_sub` может переполниться раньше, чем окончательно сокращённая дробь, поэтому оценка для него отдельная.

**Задачи.**
- [ ] `proptest` в `sciwhisper-core` (dev-dependency). Свойства:
  - если `Some(c)`: $A c = 0$, все $c_j > 0$, $\gcd(c) = 1$, $c_j \le 9999$;
  - перестановка веществ переставляет коэффициенты (эквивариантность); перестановка элементов в формулах ничего не меняет;
  - умножение уже сбалансированной реакции на $k$ не меняет ответ;
  - генератор «сбалансированных по построению» реакций (взять случайный положительный $c$ и подобрать формулы) → ответ равен примитивной части $c$, если $\dim\ker A = 1$;
  - никаких паник на любых входах, включая огромные счётчики.
- [ ] **Независимая реализация** для дифференциального тестирования: версия на `num-rational` + `num-bigint` (без переполнений) внутри тестов. Свойство: `i128`-версия возвращает либо то же, что big-версия, либо `None`, и `None` только когда big-версия реально выходит за `i128` (или коэффициент больше 9999). Дополнительно — офлайн-сверка с SymPy (`Matrix.nullspace()`) на выгрузке случайных матриц.
- [ ] Записать и доказать в `docs/` оценку отсутствия переполнения через Адамара. Проверить её тестом на граничных матрицах.
- [ ] **ЧЕРНОВИК: режим для $\dim\ker A \ge 2$.** Не вставлять, а показывать пользователю базис независимых реакций. Это исследовательское расширение, в продукт — только после обсуждения.
- [ ] **Опционально: Lean 4 + Mathlib.** Формализовать: «если $\dim\ker A = 1$ и в ядре есть строго положительный вектор, то примитивный положительный вектор в ядре единственен». Это доказательство **математики**, а не Rust-кода. Связь с кодом остаётся через proptest. Верифицировать сам Rust (например, инструментами вроде Kani или Prusti) — отдельная большая тема, сюда не включать.

**Критерий готовности.** В CI гоняются proptest-свойства (фиксированный seed для воспроизводимости и отдельный job с большим числом случаев), дифференциальный тест против BigRational проходит, в `docs/` есть доказательство оценки переполнения, написанное собственноручно.

**Оценка:** proptest и генераторы 3–4 вечера; BigRational-эталон 2–3; оценка Адамара 2–4; Lean — 10–20 вечеров с нуля (оценка очень неточная, зависит от опыта с Lean).

### Исследовательские постановки

**Постановка №1. Помогает ли грамматика выбирать среди гипотез ASR?**
- *Вопрос:* улучшает ли выбор среди K гипотез Whisper по комбинированному скору (ASR + грамматика) точность AST на живых дикторах по сравнению с top-1 Whisper + текущий разборщик?
- *Гипотеза:* да, на научных фразах, потому что ошибки ASR в терминах («гидроксит», «дробь»/«дробью») часто дают неразбираемый или маловероятный по PCFG вариант, а правильный есть среди K.
- *Эксперимент:* K ∈ {1, 2, 4, 8}, λ подбирается на dev по дикторам. Одна оценка на замороженном test.
- *Базовая линия:* top-1 Whisper с теми же параметрами + текущий `interpret_utterance`. Вторая база: «первая разбираемая гипотеза» (без PCFG).
- *Метрики:* AST exact match (главная, парно: Макнемар + кластерный бутстрэп по дикторам); oracle@K; WER; false scientific rewrite rate на прозе (не должна расти).
- *Отрицательный результат:* разница с базой в пределах интервала или ниже заранее записанного минимального эффекта. Либо oracle@K почти равен top-1 (правильного варианта нет среди гипотез — тогда узкое место в акустике, а не в выборе). Либо рост ложных переписываний прозы съедает выигрыш. Любой из этих исходов публикуется как результат.

**Постановка №2. Можно ли откалибровать уверенность разборщика?**
- *Вопрос:* даёт ли откалиброванная модель уверенности (признаки ASR + грамматики) меньший риск при том же покрытии, чем четыре ручных уровня с порогом 0.9?
- *Гипотеза:* да. Ручные уровни не видят неуверенности ASR, а она по построению основной источник ошибок на живой речи.
- *Эксперимент:* логистическая регрессия и изотоническая калибровка, кросс-валидация по дикторам, итог на test.
- *База:* текущие 1.0/0.95/0.7/0.0 + порог 0.9 (и лучший порог по той же сетке, `THRESHOLD_GRID`).
- *Метрики:* AURC, риск при покрытии, равном покрытию базы; ECE + Brier + log loss; reliability diagram.
- *Отрицательный результат:* AURC не лучше базы в пределах интервала или ошибок меньше, чем нужно для подгонки (правило `MIN_ERRORS_TO_FIT` уже в коде). Тогда вывод «на N дикторах калибровка не отличима от ручных уровней, нужно ≥ M ошибок», где M оценивается из данных.

Предрегистрировать обе постановки в `research/` до прогона на test, по образцу уже существующего `reranker/program.md`.

## Риски

- **Данные.** Дикторы не находятся или записывают мало. Меры: маленький первый батч (5 × 40 фраз), повторная запись позже. Интервалы при N дикторов будут широкими — это нормально, главное их честно показать.
- **Юридическое.** Голос — персональные данные. Публикация без корректного согласия недопустима. До публикации датасета нужна консультация юриста. Если согласие не покрывает публикацию, датасет остаётся закрытым, публикуются только агрегаты и код.
- **Долг понимания.** Около 31 тыс. строк в `experimental` за две недели, ветки `codex/*`. Риск: защищать в разговоре с лабораторией то, что сам не выводил. Мера: блок-задачи «выведи и сверь» из этапа 5 до новых фич.
- **Утечка test.** `dev_holdout` уже открывался (репозиторий сам это признаёт). Новый test — только из живых голосов, заморозить хешем и открыть один раз на постановку.
- **N-best у Whisper.** Может оказаться дорого (см. 3Б, ЧЕРНОВИК). Запасной путь — сэмплирование с температурой. Отрицательный результат постановки №1 тоже результат.
- **Распыление.** Продуктовые задачи (Windows-упаковка, трей, Word) съедают вечера. Правило: на время этапов 2–4 продуктовые изменения — только баг-фиксы.
- **Переписывание истории** (удаление PNG) ломает ссылки и форки. Делать только осознанно, один раз, либо не делать вовсе.
- **Переобучение на своих данных.** Словари и эвристики подогнаны под фразы автора. Меры: свободные формулировки дикторов, разбиение по дикторам, фиксированный протокол.

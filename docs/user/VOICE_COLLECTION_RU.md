# Записать голосовой набор для проверки sci-witch

В программе есть пошаговый сборщик `collect-voice`. Он показывает задания,
записывает голос, позволяет прослушать попытку и перезаписать её. После
подтверждения запись остаётся на диске. Прерванную сессию можно продолжить.
Это терминальный интерфейс; отдельного окна в трее пока нет.

Записи сохраняются локально. Команда не запускает Whisper, не отправляет
данные и не обучает модель. Модель и доступ в интернет для сбора не нужны.
Для оценки распознавания используется отдельная существующая команда `ingest`.

## Начало

Не создавайте папку сессии заранее: `start` создаёт её сам и требует, чтобы её не было. На Windows команды можно выполнять в
PowerShell, открытом рядом с `sciwhisper.exe` (тогда используйте `./sciwhisper.exe`).
Пример ниже записывает сессию в новую папку `my-voice-session`:

```text
sciwhisper collect-voice start --session my-voice-session --speaker spk01 --split train --consent consent-ru-v2 --date 2026-09-12 --environment quiet_room
```

Параметр `--consent` обязателен и значения по умолчанию не имеет: без него `start` не запускается. Выбор описан в разделе «Два согласия» ниже.

Укажите фактическую дату согласия. Код диктора: `spk` и две цифры, от `spk01` до `spk99`. Протокол voice-v1 использует `spk01`–`spk05`;
`spk00` не принимается. Назначьте каждому диктору свой код и используйте его повторно для этого человека. Не включайте
имя, адрес или аккаунт в код диктора и описание обстановки. Голос сам по себе
может позволить узнать человека; код не делает запись анонимной.

## Два согласия

| `--consent` | Что это | Подтверждение в терминале | Куда можно использовать запись |
|---|---|---|---|
| `consent-ru-v2` | Бумажная форма [`research/data/consent-ru-v2.md`](../../research/data/consent-ru-v2.md), которую диктор подписывает до записи | оператор вводит `ПОДПИСАНО` | корпус voice-v1; публикация возможна только после проверки формы юристом |
| `voice-local-v1` | Короткий текст на экране | диктор вводит `СОГЛАСНА` или `СОГЛАСЕН` | только локально, у вас на компьютере |

Протокол [voice-v1](../../research/protocol/voice-v1.md) требует `consent-ru-v2`.
Для него программа называет файл формы и показывает SHA-256 его текста, а затем
просит ввести `ПОДПИСАНО`. Вводите слово, только если диктор уже подписал
бумажную форму: программа подпись не проверяет. В сессию записываются
`statement_id: consent-ru-v2` и SHA-256 текста формы из репозитория на момент
записи; сам текст лежит в `consent.txt`. Если файл формы изменить, сессию
этой версии больше нельзя открыть; изменённый текст получает новое имя.

Записи `voice-local-v1` в опубликованный корпус не попадают никогда. Терминал
и `pack.json` (`"scope": "local_only"`) говорят, что они только локальные, а
`ingest` отказывает на таких записях и просит повторить запись с `consent-ru-v2`.
Если записи нужны для корпуса, их надо записать заново. Отказ при вводе
подтверждения не создаёт сессию.

После согласия выберите микрофон из списка или укажите `--mic "имя устройства"`.
Системное имя выбранного микрофона сохраняется в записи. При его отключении
программа сообщает ошибку; подключите устройство или продолжите с другим `--mic`.
Устройства с одинаковым именем пока неразличимы.

Одна попытка ограничена восемью секундами; `--seconds 20` меняет предел
(от 1 до 60 секунд). Enter завершает запись раньше. `q` во время
записи отменяет попытку. Затем `p` воспроизводит её, `r` позволяет повторить,
а `a` предлагает подтвердить текст. Принимать можно только прослушанную запись.
Подтвердите её (`ТОЧНО`), только если произнесли фразу задания полностью, без перефразирования. При оговорке перезапишите: эталонный AST относится к исходному заданию. У свободного задания (см. «Свободные задания») `ТОЧНО` не просят: подтверждение — `ДА`.

`s` пропускает задание до следующего запуска. `q` между заданиями сохраняет прогресс и выходит; сессию можно продолжить. Во время просмотра попытки `q` удаляет временную попытку и выходит.

```text
sciwhisper collect-voice status --session my-voice-session
sciwhisper collect-voice resume --session my-voice-session
```

Сохранённые записи повторно не предлагаются. Два процесса не могут изменять
одну сессию одновременно. Повреждённое аудио или изменённые метаданные приводят
к ошибке проверки. После аварийного завершения неопубликованная попытка не
считается подтверждённой; остатки `.pending-*` удаляются при отзыве согласия.
При обычной отмене временные файлы удаляются автоматически. Принудительное
завершение процесса или отключение питания может оставить временные файлы ОС.

## Локальный пакет

```text
sciwhisper collect-voice export --session my-voice-session --output my-voice-pack
```

Папка назначения должна быть новой. После подтверждения (`ЭКСПОРТ`) создаются:

- `dataset.jsonl` — подтверждённые записи по схеме корпуса 2;
- `audio/` — моно WAV, PCM16, 16 кГц;
- `consent.txt` — текст согласия (для `consent-ru-v2` — текст формы из репозитория);
- `pack.json` — версия сборщика, SHA-256 исходного плана, `consent_statement_id`
  и `consent_sha256`, `scope` (`local_only` для `voice-local-v1`,
  `publication_after_legal_review` для `consent-ru-v2`), число готовых и
  запланированных записей, ОС и SHA-256 файлов пакета.

Это папка, которую можно упаковать обычным архиватором. Экспорт сам не является
согласием на передачу или публикацию. Пакет с `voice-local-v1` передавать
нельзя; для пакета с `consent-ru-v2` публикация ждёт проверки формы юристом. `ingest` отказывает на записях `voice-local-v1`. Сборщик не запускает распознавание, поэтому `asr_hypotheses` во встроенном плане пусты; при `--tasks` они переносятся из исходного файла.

```text
sciwhisper ingest --manifest my-voice-pack/dataset.jsonl --output my-voice-pack/transcribed.jsonl
sciwhisper-eval validate-dataset --dataset my-voice-pack/transcribed.jsonl
```

Выход `ingest` должен находиться в той же папке, чтобы относительные пути
`audio/` продолжали указывать на правильные файлы. Для измерений без Whisper
добавьте `--describe-only`. Команда `sciwhisper-eval` доступна разработчикам
из рабочего дерева, а не обязательно в пользовательском архиве.

## Отзыв согласия

```text
sciwhisper collect-voice revoke --session my-voice-session
```

После ввода `УДАЛИТЬ` программа запрещает запись и экспорт этой сессии, затем
удаляет её аудио и подтверждения. Операцию можно повторить после прерывания.
Остаются план и отметка отзыва. Удаление необратимо средствами приложения.
Экспортированные копии программа не отслеживает: удалите их отдельно вместе
с производными файлами `ingest`. Это обычное удаление файлов, не гарантированное
стирание с накопителя и резервных копий.

## Свободные задания

Протокол [voice-v1](../../research/protocol/voice-v1.md) даёт карточки
`voice-v1-free-01`…`08`: диктор отвечает своими словами, готовой фразы нет.
В `--tasks` такое задание — строка JSONL с `"delivery": "free"` и полем `card`
(текст для диктора); gold (`target_domain`, `target_action`, `target_ast`) и
остальные поля те же, что у чтения. Поля `human_transcript` у такой строки быть
не должно: расшифровку пишет человек после записи, и план её не задаёт.
Строка с `human_transcript`, без `card` или с `reference_status` отклоняется.
Чтение — `"delivery": "scripted"` или без поля; карточка у него не допускается.
Карточка — непустой текст без управляющих символов, не длиннее 1024 байт.

```text
{"dataset_schema_version":1,"id":"voice-v1-free-02-a","family_id":"voice-v1-free-02","provenance":"handcrafted_text","delivery":"free","card":"Назовите воду как химическое вещество своими словами.","target_domain":"chemistry","target_action":"ast","target_ast":{ как у чтения },"split":"train","tags":[]}
```

Диктор видит `Карточка: …` вместо фразы. Запись, прослушивание (`p`) и
перезапись (`r`) те же. Подтверждение — после прослушивания ввод `ДА`: запись
годится, диктор ответил на карточку, голос слышно. `ТОЧНО` не нужно, потому что
сверять не с чем. В сохранённой записи и в `dataset.jsonl` у такого задания
`human_transcript` равен `""`, а `reference_status` равен `"pending"`.

Что было сказано на самом деле, вписывает человек (разметка по протоколу). Пока
расшифровка не вписана, `reference_status` остаётся `pending`; по завершении
разметки его меняют на `final` или убирают. Схема корпуса принимает пустой
`human_transcript` только при `pending`; запись с `final` (или без поля) и пустой
расшифровкой отклоняется. `ingest` оставляет `human_transcript` и
`reference_status` как есть и не придумывает расшифровку.

Отчёты `sciwhisper-eval` считают записи с `pending` отдельно от чтения фраз:
пока это не сделано, такая запись для отчёта не отличается от остальных, и пустая
расшифровка попадёт в метрики. Не подавайте отчётам набор с `pending`, пока
эта часть не готова.

## Как не испортить исследовательские данные

По умолчанию встроены задания `dev-seed-v2`; команда выбирает из них только
указанный `--split`: `train`, `validation` или `dev_holdout`. Один диктор должен
принадлежать одному split во всех сессиях. Сборщик видит только одну сессию и не сверяет диктора с другими;
после объединения пакетов запустите `validate-dataset` на общем файле: он завершается ошибкой
при утечке дикторов или семейств между split. Повторный микрофон или повторная сессия не делают нового диктора.

`--tasks path/to/plan.jsonl` принимает другой заранее размеченный текстовый
корпус. План и его SHA-256 фиксируются при создании сессии. Эталонные ответы
копируются из него, не вычисляются парсером. Задания бывают двух видов: чтение
фразы и свободное (см. «Свободные задания»). Встроенный dev-корпус
уже используется при разработке и не заменяет независимый frozen test.

Начало и конец WAV сохраняются целиком после приведения в моно и 16 кГц:
VAD ничего не вырезает. Его вывод показывается только как подсказка. Отсутствие
обнаруженной речи не превращается в выдуманный SNR; поле остаётся пустым.
Лимит — 1000 заданий, 60 секунд на запись (около 1,92 МБ каждая).

Запуск на реальном микрофоне, воспроизведение через Windows SoundPlayer и весь
интерактивный проход требуют ручной приёмки. Автоматические тесты используют
синтетические WAV и проверяют хранение, согласие, экспорт и совместимость схемы.

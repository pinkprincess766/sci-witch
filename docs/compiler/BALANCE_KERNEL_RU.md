# Балансировка: когда положительное решение одно

Черновик от 28.09.2026 к блоку A плана. Это конспект утверждения, с которым
сверяется `balance_equation`. По правилу этапа 5 его нужно заново вывести
на бумаге самому; пока этого нет, файл не считается собственноручным
доказательством.

Код: `crates/sciwhisper-core/src/balance.rs`. Матрица `A` имеет строку на
каждый элемент и, если у какого-то вещества ненулевой заряд, ещё строку
заряда. Столбцы — вещества слева направо, правая часть со знаком минус.
`balance_equation` возвращает коэффициенты только когда после RREF свободный
столбец ровно один.

## Утверждение

Пусть `A` — матрица размера `r × n` над полем рациональных чисел, `n ≥ 1`.
Множество строго положительных решений `Aν = 0` является одним лучом
(любые два таких решения пропорциональны с положительным коэффициентом)
тогда и только тогда, когда `dim ker A = 1` и в ядре есть хотя бы один
строго положительный вектор.

В этом случае среди целочисленных векторов ядра есть ровно один строго
положительный примитивный вектор: все координаты больше нуля и их НОД равен 1.

## Почему это совпадает с кодом

RREF не меняет ядро. Число свободных столбцов равно `n − rank A`, а по
теореме о ранге и дефекте это `dim ker A`. Ветка `let [free] = free_cols`
принимает ответ только при `dim ker A = 1`. Дальше код ставит свободную
переменную в 1, восстанавливает остальные координаты, приводит к целым,
отбрасывает вектор с нулём или со смешанными знаками, делит на НОД и
отказывается, если коэффициент больше 9999 или не помещается в `u32`.
Отказ при `dim ker ≠ 1` как раз и есть воздержание, когда луч не один.

## Вывод

1. `dim ker A = n − rank A`.
2. При `dim ker A = 0` ядро — только нулевой вектор. Он не строго
   положительный.
3. При `dim ker A = 1` ядро — это все рациональные кратные одного
   ненулевого вектора `v`. Строго положительные решения существуют ровно
   тогда, когда какой-то ненулевой кратный `v` строго положителен, и тогда
   все они — положительные кратные этого вектора. Другого направления в
   ядре нет.
4. При `dim ker A ≥ 2`, если в ядре уже есть строго положительный `v`,
   берётся любой `w` из ядра, не пропорциональный `v`. Для достаточно
   маленького `ε ≠ 0` вектор `v + εw` тоже строго положителен: каждая
   координата `v` положительна и выдерживает маленькую добавку. `v` и
   `v + εw` не пропорциональны, иначе `w` был бы кратен `v`. Значит
   положительных направлений больше одного.
5. Целый примитивный вектор. У рациональной матрицы в одномерном ядре есть
   ненулевой целый вектор: у рационального базисного вектора очищаются
   знаменатели. Если есть строго положительное решение, среди целых векторов
   ядра есть строго положительный. Деление на НОД координат даёт примитивный
   положительный вектор `c`. Если `c'` — другой такой же, то `c' = (p/q) c`
   с целыми `p, q > 0` без общего делителя. Тогда `q c' = p c`. Из
   `НОД(c) = 1` следует `q = 1`, из `НОД(c') = 1` следует `p = 1`, поэтому
   `c = c'`.

Пункт 4 объясняет, почему при двух и более свободных столбцах код не
выбирает «минимальную» балансировку: их больше одной, и это разные реакции
в одной записи.

## Что уже проверяет тест

`crates/sciwhisper-core/tests/balance_props.rs` не доказывает теорему. Он
проверяет следствие для тех входов, которые генератор успевает подать:

- если функция вернула `c`, то `A c = 0` на атомах и заряде, все `c_j`
  от 1 до 9999, НОД равен 1;
- перестановка веществ внутри левой части и внутри правой переставляет
  коэффициенты так же. Это и есть единственность примитивного вектора:
  от порядка столбцов он зависеть не может;
- реакция, собранная из выбранных коэффициентов (у каждого левого вещества
  свой элемент, правая формула — их взвешенная сумма), даёт ровно этот
  примитивный вектор;
- умножение уже сбалансированной реакции на `k` меняет только продиктованные
  коэффициенты и не меняет ответ;
- перестановка частей внутри формулы не меняет ответ;
- реакция с числами атомов порядка миллионов, лежащая внутри доказанной
  ниже области, даёт точный ответ (`large_counts_inside_the_proven_region_…`).

Эталон на больших целых и режим `dim ker ≥ 2` в этом файле не делаются.
Они следуют в плане дальше. Оценка переполнения — в следующем разделе, её
тесты в `crates/sciwhisper-core/src/balance.rs`.

## Когда `i128` не переполняется (бэклог B2)

Вывод владелец на бумаге не перепроверял. Места, где он не доказан до
конца, помечены словом «НЕ УВЕРЕН» и собраны в конце раздела.

### Утверждение

Пусть `A` — целая матрица `r × n` на входе `rref`, `m = min(r, n)`. Для
строки `a_i` и столбца `a^j` положим `‖·‖` — евклидова норма. Определим

```
B_row = произведение m наибольших значений max(1, ‖a_i‖) по строкам,
B_col = произведение m наибольших значений max(1, ‖a^j‖) по столбцам,
B     = min(B_row, B_col).
```

Если `B ≤ 2^42 − 1`, то ни одна операция `checked_*` в `rref`,
в сборке вектора `x`, в НОК знаменателей и в переводе к целым не вернёт
`None`. Константа в коде — `HADAMARD_LIMIT = 2^42 − 1`. Условие достаточное,
не необходимое: при `B` выше предела `balance_equation` может и сбалансировать,
и отказаться; оно только не гарантирует ничего.

### Вывод

Через `M` обозначим наибольшее по модулю значение среди всех квадратных
миноров `A` размера от 1 до `m`.

**Шаг 1. Адамар даёт `M ≤ B`.** Неравенство Адамара: для квадратной
матрицы `|det| ≤ произведение норм её строк`, то же для столбцов. Минор
размера `k ≤ m` на строках `S`, столбцах `C`: `|det A[S,C]| ≤ ∏_{i∈S} ‖a_i|_C‖`.
Усечённая строка не длиннее целой: `‖a_i|_C‖ ≤ ‖a_i‖ ≤ max(1, ‖a_i‖)`. Все
множители `max(1, ·) ≥ 1`, а `|S| = k ≤ m`, поэтому произведение по `S`
не больше произведения `m` наибольших: `|det A[S,C]| ≤ B_row`. Для
столбцов то же самое, значит `M ≤ min(B_row, B_col) = B`. Единица в
`max(1, ·)` нужна, чтобы нулевая строка не обнуляла границу.

**Шаг 2. Что лежит в матрице после `k` шагов.** Пусть сделано `k` шагов
с опорными столбцами `C = (c_1..c_k)`. Пусть `I` — множество исходных
строк, ставших опорными (при обмене строк через `a.swap` строка остаётся
той же исходной строкой). Положим `Δ_k = |det A[I,C]|`, `Δ_0 = 1`.

- Опорная строка на каждом шаге есть исходная строка плюс комбинация
  прежних опорных; поэтому опорные строки состояния — комбинации строк `I`.
  Каждый опорный столбец обнулён во всех строках, кроме своей, где стоит
  1. Значит, опорные строки равны `A[I,C]^{-1} · A[I,:]`, и по правилу
  Крамера элемент `(p, j)` равен `det A[I, C с c_p заменённым на j] / det A[I,C]`.
- Неопорная строка `r` — исходная строка плюс комбинация строк `I`, с
  нулями в столбцах `C`. Значит, она равна `A[r,:] − A[r,C] A[I,C]^{-1} A[I,:]`,
  и по формуле Шура для определителя элемент `j` равен
  `det A[I∪{r}, C∪{j}] / det A[I,C]`.
- Свежая опорная строка `s` (после деления на опорный элемент, до
  исключения; `I`, `C` — прежние, `c` — новый столбец) — отношение двух
  миноров размера `k`: `det A[I∪{s}, C∪{j}] / det A[I∪{s}, C∪{c}]`, а знаменатель
  здесь и есть `Δ_k`.
- `Δ_k ≠ 0`: опорный элемент ненулевой, а он равен `±Δ_k / Δ_{k−1}`.

Итог: каждая ячейка состояния — рациональное число `N / Δ_k`, где `N` —
минор размера не больше `k ≤ m`. `Frac::reduced` сокращает дробь на НОД,
значит хранимая пара удовлетворяет `|num| ≤ |N| ≤ M` и `den | Δ_k`, то есть
`den ≤ Δ_k ≤ M`. Это **лемма хранения**: после каждого шага `|num| ≤ M`,
`den ≤ M`.

**Шаг 3. Деление на опорный элемент** (`checked_div`). Вычисляются
`cell.num · pv.den` и `cell.den · pv.num`: оба множителя каждого
произведения — хранимые значения старого состояния, поэтому каждое
произведение не больше `M²`. Результат сокращён и по шагу 2 не больше `M`.

**Шаг 4. Произведение `factor · pivot_value`** (`checked_mul`).
Оба — хранимые значения (старое `factor`, новое `pivot_value`), поэтому
`num` и `den` до сокращения не больше `M²`. После сокращения `o` — не больше.

**Шаг 5. Вычитание** (`checked_sub(self, o)`): вычисляются
`self.num · o.den`, `o.num · self.den` и `self.den · o.den`. Здесь `self` —
хранимое (≤ `M`), `o` — до `M²`. Поэтому два первых члена не больше `M·M² = M³`,
их разность не больше `2M³`, знаменатель не больше `M³`. Это самое большое
число, которое `rref` вообще формирует: `max = 2M³`.

**Шаг 6. Порог.** `i128::MAX = 2^127 − 1`. Условие `2M³ ≤ 2^127 − 1`
выполняется при `M ≤ 2^42 − 1`, потому что `2·(2^42)³ = 2^127` уже
не помещается, а `2·(2^42 − 1)³ < 2^127`. С шагом 1 достаточно `B ≤ 2^42 − 1`.

**Шаг 7. Остаток `balance_equation`.** После `rref` ранг `ρ ≤ m`, свободный
столбец один, `Δ = Δ_ρ`.

- `x[свободный] = 1`; для опорных: `x = 0 − matrix[row][free]`, это
  `checked_sub` от нуля: `0·den − num·1`, не больше `M` по лемме хранения.
  Знаменатель каждой `x_j` делит `Δ`, а числитель по модулю — минор, то
  есть не больше `M`.
- НОК: текущее `lcm` всегда делит `Δ` (НОК делителей `Δ` делит `Δ`), поэтому
  `(lcm / g) · den ≤ Δ ≤ M`.
- Перевод к целым: `num · (lcm / den)` равно `|x_j| · lcm ≤ |N|·lcm/Δ ≤ M`.
- `checked_neg` для чисел не больше `M` не переполняется. Остальное
  (`НОД`, деление, `u32::try_from`, предел 9999) переполнения `i128` не даёт;
  отказ там — отказ по смыслу, не по арифметике.

Так что при `B ≤ 2^42 − 1` `None` из `balance_equation` возможен только по
причинам содержания: размерность ядра не 1, смешанные знаки, нули,
коэффициент больше 9999, переполнение подсчёта атомов в `u64`
(`atom_counts`, отдельная проверка до матрицы).

### Что покрывает порог

Для матрицы `r × (r+1)` со всеми элементами не больше `e` по модулю
`B ≤ (e·√(r+1))^r`. Наибольшее `r`, при котором это не выше `2^42 − 1`:

| `e` (наибольший индекс) | 1 | 2 | 4 | 9 | 30 | 100 | 1000 | 10000 |
|---|---|---|---|---|---|---|---|---|
| наибольшее `r` | 19 | 14 | 11 | 8 | 6 | 5 | 3 | 2 |

Честный вывод: оценка доказывает безопасность для реакций с числом
элементов (плюс строка заряда) до 8 при индексах до 9 и до 11 при
индексах до 4. Для 20 элементов и 21 вещества с индексами до `2^32`
(тест `balance_equation_abstains_when_elimination_overflows`) `B` порядка
`2^647` намного выше порога, и там переполнение настоящее. Матрица из теста
`large_full_rank_system_never_panics` (20×21, индексы 1–9) тоже выше порога
(`B` порядка `2^93`), хотя фактически не переполняется: оценка грубая.
Грубость идёт из трёх мест: неравенство Адамара нечувствительно к
зависимости строк; `M³` берётся как оценка трёх разных миноров одним
наибольшим; произведение `factor · pivot_value` считается до сокращения.
Настоящий пик в моей сверке был не выше `M³` (отношение к `2M³` равно 0,5).
Эта сверка шла одноразовым скриптом вне репозитория, в тесты не вошла.

### Как это устроено в коде

- `HADAMARD_LIMIT` — константа предела (`2^42 − 1`).
- `hadamard_bound_sq` считает `B²` точно в `u128`: суммы квадратов и
  произведения с `checked_*`. Плавающей запятой нет, поэтому нет и
  вопроса об ошибке округления. `None` значит, что `B²` не влезло в `u128`
  (это заведомо выше предела).
- `elimination_is_proven_safe` сравнивает `B²` с `HADAMARD_LIMIT²`.
- `balance_equation` в отладочной сборке считает это условие до `rref` и
  через `debug_assert!` требует, чтобы `rref` не вернул `None`, если условие
  выполнено. В релизной сборке этого кода нет, ответы функции не меняются.
- Новых `pub` нет: `public_surface.rs` не затронут.

### Тесты

Все в `balance.rs`, кроме последнего:

- `limit_is_the_exact_boundary_for_a_single_entry`: матрица 1×1 с
  элементом `HADAMARD_LIMIT` безопасна, с `HADAMARD_LIMIT + 1` — нет.
- `matrix_just_under_the_limit_balances_without_a_checked_failure` и
  `matrix_just_over_the_limit_is_not_proven_safe`: матрица 2×3, `B²` на 0,3%
  ниже предела (ответ `[2, 3, 1]`) и на 0,0001% выше.
- `the_overflowing_20_by_21_system_is_above_the_limit`: тот же 20×21,
  что в тесте переполнения, выше предела; а наибольшая одна строка ниже
  предела, то есть граница из одного множителя назвала бы его безопасным.
- `a_bound_above_the_limit_that_fits_u128_is_still_rejected`: ветка, где `B²`
  считается, но выше предела.
- `hadamard_bound_matches_hand_computed_values`,
  `hadamard_bound_dominates_every_minor`: границу сверяют с ручными
  числами и с перебором всех миноров.
- `stored_fractions_never_exceed_the_largest_minor`: лемма хранения на
  случайных малых матрицах и их префиксах по столбцам.
- `random_matrices_below_the_limit_never_overflow`: матрицы от 2×3 до 8×9
  с границей у предела; `rref` обязан вернуть `Some`.
- `large_counts_inside_the_proven_region_still_balance_exactly` в
  `balance_props.rs`: тот же случай через публичный интерфейс, в отладочной
  и релизной сборках.

### НЕ УВЕРЕН / не доказано

1. **НЕ УВЕРЕН** в шаге 2 как в строгом доказательстве: он выведен
   индукцией по шагам без записи всех выкладок и сверен тестом
   `stored_fractions_never_exceed_the_largest_minor` и одноразовой
   сверкой на модели алгоритма вне репозитория (3000 матриц, пик не выше `2M³`). Это проверка на
   примерах, не доказательство. Случай, когда опорный столбец пропущен
   (нулевой столбец), считается тривиальным, но отдельным тестом он не
   покрыт.
2. **НЕ УВЕРЕН** в шаге 7: утверждение, что все знаменатели `x_j` делят
   `Δ_ρ`. Оно следует из шага 2, но `debug_assert!` проверяет только
   `rref`, а хвост (`x`, НОК, перевод к целым) гарантирован лишь выводом и
   тем, что тесты выше возвращают `Some`.
3. Оценка `o.den ≤ M²` в шаге 4 грубая (на деле `o.den` делит `Δ_{k−1}·Δ_k`);
   на верность вывода это не влияет, только на широту области.
4. Тест `random_matrices_below_the_limit_never_overflow` берёт матрицы с
   границей у предела, но не у самых худших для исключения; он не доказывает,
   что порог `2^42` нельзя поднять. Нужен ли поднятый порог — вопрос,
   на который здесь нет ответа.
5. Эталон на больших целых (`num-bigint`) не использован: зависимость
   требует разрешения владельца.

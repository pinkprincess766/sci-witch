# Голосовой корпус: как собрать

Версия 0.3 требует измерять работу **с живым голосом**. До сих пор корпус
`dev-seed-v2` остаётся текстовым: 113 записей, ни одного аудиофайла, `ASR-first`
в отчёте помечено как `N/A`, точность распознавания не измерена вообще.

Этот документ описывает, что нужно собрать и как это попадает в лабораторию.
Код готов; **записей нет**, и выдумать их нельзя.

## 0. Второй источник: исправления пользователя

Организованная запись — не единственный путь к данным, и не первый. Каждый
раз, когда человек нажимает «Варианты прочтения» и выбирает не то, что было
вставлено, получается размеченный пример, который никому не пришлось
собирать специально: что услышано, что вставлено, что было нужно.

Включается в меню значка («Запоминать мои исправления») или командой:

```bash
sciwhisper settings set remember_corrections true
sciwhisper corrections          # посмотреть накопленное
```

**По умолчанию выключено.** Это речь пользователя на диске, и включение —
его решение, как и с `persist_history`. Файл лежит рядом с настройками,
никуда не отправляется, и ничто в работе программы от него не зависит.

Чего это НЕ даёт:

* **аудио** — журнал текстовый, поэтому `ASR-first` по нему по-прежнему не
  измерить, и ворота 0.5 он не закрывает;
* **gold-разметку** — выбранный пользователем текст это выбор, а не
  проверенный ответ; превращать его в `target_ast` повторным разбором
  значило бы получить gold из парсера, что [research/README_RU.md](../README_RU.md)
  запрещает. Разметка остаётся человеческим шагом.

Что это даёт: список мест, где система ошибается **у настоящего человека на
настоящих фразах**, и он накапливается сам. Для раздела 1 это готовый
список фраз, которые стоит записать голосом в первую очередь.

## 1. Что именно собирается

| Параметр | Требование | Почему |
|---|---|---|
| Дикторов | не меньше 10 | меньше — и число говорит о конкретных людях, а не о системе |
| Фраз на диктора | 30–60 из корпуса `dev-seed-v2` | те же цели, что уже размечены вручную |
| Микрофоны | не меньше трёх разных | гарнитура, ноутбучный, петличка |
| Обстановка | тихая комната **и** шумная | 0.3 — про живой голос, а не про студию |
| Формат файла | WAV, 16 бит, моно, 16 кГц | сжатие превратило бы артефакт кодека в «ошибку распознавания» |
| Согласие | письменное, до записи | без него запись не попадает в корпус |

Отдельно нужны **отказные** записи: обычная речь, которая не должна
превращаться в формулу («предел терпения», «вода закипела в чайнике»).
Без них `FalseScientificRewriteRate` на голосе не измеряется.

## 2. Согласие

Схема корпуса не даст записать голос человека без блока `consent`:
загрузчик отказывает, если `granted` не `true`, если не назван текст
согласия или нет даты (`schema.rs`, тест
`a_recording_of_a_person_without_consent_is_refused`).

Шаблон текста — [`consent-ru-v1.md`](consent-ru-v1.md). Это **черновик,
написанный инженером, а не юристом**: перед сбором его нужно прочитать и,
если записи будут где-то опубликованы, показать юристу. `statement_id` в
записи должен совпадать с версией текста, который человек реально подписал.

## 3. Манифест

Один JSONL-файл, одна строка на запись. Человек заполняет то, что знает
только человек:

```json
{"id":"voice-water-001-spk01","family_id":"voice-water-001","provenance":"real_audio",
 "human_transcript":"вода","target_domain":"chemistry","target_action":"ast",
 "target_ast":{"Chemical":{"Species":{"coefficient":1,"formula":{"parts":[
   {"Atom":{"symbol":"H","count":2}},{"Atom":{"symbol":"O","count":1}}]},
   "charge":null,"marker":null}}},
 "split":"train","tags":["voice","formula"],"speaker_id":"spk01",
 "audio":{"file":"audio/spk01-0001.wav","microphone":"Logitech H390","environment":"quiet_room",
   "consent":{"granted":true,"statement_id":"consent-ru-v1","date":"2026-09-05"}}}
```

Путь в `audio.file` — относительно самого манифеста, выход за его каталог
запрещён.

## 4. Заполнение измеримого

```bash
cargo run -p sciwhisper-cli -- ingest \
  --manifest research/data/voice-v1.manifest.jsonl \
  --output research/data/voice-v1.jsonl
```

Команда читает каждый WAV и **сама** проставляет `sha256`, `duration_secs`,
`sample_rate_hz`, `channels` и `snr_db` (по VAD), затем прогоняет файл через
Whisper и записывает результат в `asr_hypotheses`. Значения, заранее
вписанные в манифест руками, перезаписываются измеренными — иначе в корпусе
завелись бы числа, которых никто не мерил.

Что она делать отказывается:

* заполнять `human_transcript`, `target_*`, `speaker_id` — это разметка;
* принимать запись человека без согласия — проверка идёт **до** чтения
  аудио, чтобы отказ был мгновенным;
* принимать не-WAV;
* придумывать SNR для дорожки, в которой VAD не нашёл речи (поле просто
  отсутствует, а запись называется в конце прогона).

Флаг `--describe-only` меряет аудио, не запуская распознавание: удобно
проверить свежую партию до того, как тратить час процессорного времени.

Затем — обычная проверка схемы:

```bash
cargo run -p sciwhisper-eval -- validate-dataset --dataset research/data/voice-v1.jsonl
```

## 5. Разбиение по дикторам

Диктор не должен встречаться больше чем в одном split. Иначе `dev_holdout`
измеряет, насколько хорошо система знает **этот голос**, а не насколько
хорошо она справляется с новым. Проверка встроена в аудит (`split.rs`,
`leaking_speakers`) и роняет прогон так же, как утечка семейства.

Практически: сначала разложить дикторов по split, потом внутри диктора —
фразы, следя за тем, чтобы семейство тоже не разъехалось.

## 6. Что появится в отчёте

Как только в корпусе будут записи с `asr_hypotheses`:

* `ASR-first` перестанет быть `N/A` и получит настоящее число;
* `oracle transcript` начнёт показывать реальный прирост — «сколько мы
  потеряли на распознавании», отдельно от «сколько потеряли на грамматике»;
* появится смысл в разрезах по микрофону, обстановке и SNR.

Ни одно из этих чисел нельзя получить из текста, и ни одно не будет
напечатано, пока записей нет.

# `research/` — исследовательский контур sci-witch

Здесь живут данные, схемы и результаты измерений. Здесь **нет** кода приложения: лаборатория читает `sciwhisper-core` как чёрный ящик через публичный API и ничего в нём не меняет.

```
research/
├── data/
│   ├── build_dev_seed.py          # генератор корпуса; gold пишется руками
│   ├── dev-seed-v1.jsonl          # 113 записей, dataset_schema_version 1
│   └── dev-seed-v1.manifest.json  # sha256, состав, границы применимости
├── schema/
│   ├── CANONICAL_AST_V1_RU.md     # контракт канонического AST
│   └── severity-v1.json           # машиночитаемая taxonomy тяжести ошибок
├── reranker/
│   ├── README_RU.md               # решение: обучаемый reranker пока не строится
│   └── program.md                 # предзарегистрированная программа на будущее
└── results/
    └── deterministic-v1.json      # замороженный отчёт baseline
```

Практическое руководство по запуску — [`docs/development/ML_LAB_RU.md`](../docs/development/ML_LAB_RU.md).

## Что это за корпус

`dev-seed-v1` — **текстовый корпус разработки**. Это не frozen test и не запись живых голосов:

* аудио нет вообще;
* `asr_hypotheses` пуст у всех 113 записей, поэтому **точность ASR здесь не измеряется**, а категория ошибок `ASR-first` помечена как `N/A`;
* `speaker_id` везде `null`: схема запрещает выдумывать говорящего там, где не было записи;
* акцент, SNR и микрофон не указаны, потому что их не было.

Все записи имеют `provenance: handcrafted_text`. Схема различает `handcrafted_text`, `synthetic_text`, `tts` и `real_audio` и не даёт тексту притвориться голосом: запись без аудио не может нести ни ASR-гипотезы, ни `speaker_id`.

Разделение выполнено **по семействам**: парафразы одной конструкции (`вода` / `аш два о`) несут один `family_id` и никогда не попадают в разные split. Проверка утечки — часть `validate-dataset` и отдельный тест.

## Откуда взялся gold

Каждый `target_ast` написан руками из смысла фразы по документированным соглашениям AST проекта. Генератор `build_dev_seed.py` не импортирует `sciwhisper-core`, не вызывает `interpret` и не запускает бинарь. Запись вида

```python
target_ast = interpret(human_transcript).ast
```

сделала бы benchmark тавтологическим и запрещена.

Часть записей помечена тегом `known-gap`: правильный ответ там **заведомо** не строится текущей грамматикой (феррит бария, «кельвинов», «паскалей»). Это найденные ограничения, а не ошибки корпуса.

## Границы применимости

* Корпус маленький. Доли редких событий имеют широкие интервалы, и читать их надо вместе с границами. Наблюдаемый ноль опасных переписываний — это `0/28`, то есть верхняя 95% граница ≈ `0.10`, а не доказанный ноль.
* `dev_holdout` — это не frozen test по протоколу: он открывался при отладке лаборатории. Настоящий frozen test заводится вместе с реальным голосовым корпусом.
* Метрика вывода останавливается **до** вставки в приложение. Путь Word COM здесь не проверяется.
